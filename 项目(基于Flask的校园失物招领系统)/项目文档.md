# 校园失物招领系统 - 项目完整文档

## 一、项目概述

校园失物招领系统是一个基于 Flask + 原生前端的 Web 应用，为校园内的师生提供失物发布、认领、审核管理、私聊沟通等服务。

- **启动方式**：`cd 后端 && python 应用入口.py`
- **访问地址**：`http://127.0.0.1:5000`
- **技术栈**：Python 3.11 / Flask / PyMySQL / JWT / BCrypt / HTML+CSS+JavaScript（原生，无框架）

## 三、后端完整说明

### 3.1 分层设计

```
HTTP请求 → 路由/ (Blueprint) → 业务/ (Service) → 数据库.py (CRUD)
             ↓                    ↓                  ↓
          参数解析/校验        业务规则判断        SQL 执行
          统一响应封装        数据加工组装        连接池管理
          鉴权装饰器          权限验证            异常处理
```

- **路由层** (`路由/`)：HTTP 请求入口，负责 URL 路由匹配、请求参数解析、调用业务层方法、统一格式封装响应。使用 Flask Blueprint 实现模块化路由。
- **业务层** (`业务/`)：核心业务逻辑所在，负责数据校验、权限判断、跨表查询、业务规则执行（如审核状态流转、3天自动隐藏等）。
- **数据库层** (`数据库.py`)：对 PyMySQL + DBUtils 连接池的二次封装，提供四个简洁的 CRUD 工具函数，业务代码通过 `with 数据库连接() as cur` 上下文管理器自动管理连接。

### 3.2 后端根目录文件详解

#### `应用入口.py` — 应用启动入口

**职责**：创建 Flask 应用实例、注册所有蓝图路由、托管前端静态资源、启动时自动迁移数据库。

**核心功能**：
- **`_自动迁移数据库()`**：启动时自动检查并添加数据库缺失的列/表，包括：
  - items 表的 `audit_feedback` 列（审核反馈）
  - teachers/students 表的 `session_token` 列（单点登录）
  - 创建 messages 表（私聊消息，含发送者/接收者复合索引）
  - items 表的 `found_at` 列（标记找回时间）
  - 所有迁移均采用"存在则跳过"策略，不破坏已有数据
- **`创建应用()`**：工厂函数，创建 Flask app 并：
  - 注册 CORS（允许跨域）
  - 注册 6 个蓝图：认证、物品、管理、消息、留言、上传
  - 配置静态文件托管：`/` 指向前端目录、`/static` 指向 CSS/JS、`/uploads` 指向上传目录
- **`app.run()`**：监听 `0.0.0.0:5000`，支持局域网访问

#### `配置.py` — 配置项

**职责**：集中管理所有可配置项。

**配置项**：
- `DB_CONFIG`：MySQL 连接参数（host/port/user/password/database/charset）
- `JWT_SECRET`：JWT 签名密钥
- `JWT_ALGORITHM`：JWT 算法（HS256）
- `JWT_EXPIRE_HOURS`：Token 过期时间（默认 24 小时）
- `MAX_CONTENT_LENGTH`：上传文件最大限制（10MB）

#### `数据库.py` — 数据库连接与 CRUD 封装

**职责**：基于 PyMySQL + DBUtils.PooledDB 创建线程安全的数据库连接池，并提供四个全局工具函数。

**连接池配置**：
- 最大连接数 10，最小缓存 2，最大缓存 5，最大共享 3
- 空闲时自动 ping 检查连接可用性

**工具函数**：

| 函数 | 用途 | 返回值 | 示例 |
|------|------|--------|------|
| `执行查询(sql, args)` | SELECT 多行查询 | 字典列表 `[{}, {}, ...]` | 物品列表、会话列表 |
| `执行单条查询(sql, args)` | SELECT 单行查询 | 字典 `{}` 或 `None` | 按 ID 查详情、检查重复 |
| `执行更新(sql, args)` | INSERT/UPDATE/DELETE | 受影响行数 `int` | 更新状态、删除记录 |
| `执行并获取自增ID(sql, args)` | INSERT 并返回 ID | 自增 ID `int` | 发布物品、发送消息 |

**使用方式**：所有函数内部使用 `with 数据库连接() as cur` 上下文管理器，自动提交/回滚/归还连接。

#### `工具.py` — 通用工具库

**职责**：提供 JWT 鉴权、密码哈希、统一响应、装饰器等基础能力。

**核心常量**：
- `身份表`：字典，映射 `"teacher"` → `("teachers", "teacher_id", "department")` 和 `"student"` → `("students", "student_id", "class_name")`
- `身份中文`：`{"teacher": "老师", "student": "学生"}`
- `编码转身份`：`{0: "student", 1: "teacher"}`

**核心函数**：

| 函数 | 功能 | 说明 |
|------|------|------|
| `成功响应(data, msg)` | 统一成功响应 | `{"code":0, "msg":"...", "data":...}` |
| `失败响应(msg, code, status)` | 统一失败响应 | 返回 JSON + HTTP 状态码 |
| `哈希密码(明文)` | bcrypt 哈希 | 10 轮加盐，返回 UTF-8 字符串 |
| `校验密码(明文, 哈希)` | 密码验证 | 返回布尔值 |
| `生成会话令牌()` | 生成随机会话令牌 | `secrets.token_hex(32)` |
| `签发令牌(id, 身份, 编号, 姓名, 会话令牌)` | 签发 JWT | payload 包含 sub/身份/编号/姓名/session/iat/exp |
| `解析令牌(令牌)` | 解析并验证 JWT | 失败抛出 `jwt.ExpiredSignatureError` 或 `jwt.InvalidTokenError` |
| `验证会话(用户ID, 用户身份, 会话令牌)` | 单点登录验证 | 查询数据库中的 session_token 与 JWT 对比 |
| `从请求获取用户()` | 从 Authorization 解析当前用户 | 返回 `{id, 身份, 编号, 姓名}` 或 `None` |

**装饰器**：

| 装饰器 | 功能 | 行为 |
|--------|------|------|
| `@需要登录` | 要求已登录 | 未登录返回 401 + `{"code":401,"msg":"请先登录"}` |
| `@需要老师权限` | 要求老师身份 | 未登录返回 401，非老师返回 403 |

### 3.3 路由层详解 (`路由/`)

#### `路由/认证.py` — 认证相关 API

**蓝图前缀**：`/api/auth`

| 接口 | 方法 | 功能 | 参数 | 返回 |
|------|------|------|------|------|
| `/register` | POST | 用户注册 | body: `{身份, teacher_id/student_id, email, password, name, department/class_name?, phone?}` | `{id, token}` |
| `/login` | POST | 用户登录 | body: `{身份, 编号, password}` | `{token}` |
| `/me` | GET | 获取当前用户信息 | Header: `Authorization: Bearer <token>` | `{id, 身份, 编号, email, name, phone, department/class_name, created_at}` |

**注册流程**：
1. 调用 `校验注册数据()` 验证所有字段
2. 调用 `检查重复()` 检查学号/工号 + 邮箱（跨表）是否已存在
3. 密码 bcrypt 哈希
4. INSERT 到对应表
5. 生成 session_token 写入数据库
6. 签发 JWT 并返回

**登录流程**：
1. 根据身份查对应表
2. 校验密码
3. 生成新 session_token（覆盖旧的，实现单点登录）
4. 签发 JWT 并返回

#### `路由/物品.py` — 物品管理 API

**蓝图前缀**：`/api/items`

| 接口 | 方法 | 功能 | 鉴权 |
|------|------|------|------|
| `/` | GET | 物品列表查询（支持 type/category/keyword/audit_status/page/size） | 否 |
| `/<id>` | GET | 物品详情（含发布者信息、浏览量+1） | 否 |
| `/` | POST | 发布新物品 | 是 |
| `/<id>` | PUT | 更新物品 | 是（仅发布者） |
| `/<id>` | DELETE | 删除物品 | 是（发布者或老师） |
| `/<id>/complete` | POST | 标记为已找到（设置 status=1, found_at=NOW()） | 是（仅发布者） |
| `/<id>/claim` | POST | 申请认领 | 是 |
| `/my` | GET | 我的发布列表（当前登录用户所有） | 是 |
| `/<id>/messages` | GET | 获取物品的所有留言 | 否 |
| `/<id>/messages` | POST | 发布留言 | 是 |

**列表查询核心逻辑**：
- 支持按 `type`（丢失/捡到）、`category`（5个分类）、`keyword`（标题/描述/地点模糊搜索）筛选
- `audit_status=1` 时只返回审核通过的物品
- **3天自动隐藏**：`WHERE (status=0 OR (status=1 AND found_at >= NOW() - INTERVAL 3 DAY))`
- 分页：默认每页 12 条，按创建时间倒序

**删除权限**：
- 老师：可删除任意物品
- 学生/老师本人：只能删除自己发布的物品

#### `路由/管理.py` — 后台管理 API（仅老师）

**蓝图前缀**：`/api/admin`

| 接口 | 方法 | 功能 |
|------|------|------|
| `/stats` | GET | 统计看板（物品总数、已找回数、待审核数、注册用户数、分类分布、审核通过率、找回率） |
| `/pending` | GET | 待审核物品列表（含发布者信息） |
| `/audit/<id>` | POST | 单条审核 `{通过: bool, 反馈: str}` |
| `/batch-audit` | POST | 批量审核 `{ids: [...], 通过: bool, 反馈: str}` |
| `/users` | GET | 用户列表（老师+学生，含发布数量统计） |
| `/notices` | GET | 公告列表 |
| `/notices` | POST | 发布公告 `{标题, 内容}` |
| `/notices/<id>` | DELETE | 删除公告 |

**批量审核**：
- 批量通过：将多条记录的 `audit_status` 更新为 1
- 批量拒绝：将多条记录的 `audit_status` 更新为 2 并设置 `audit_feedback`，同时从 items 表删除该物品

#### `路由/消息.py` — 私聊消息 API

**蓝图前缀**：`/api/messages`

| 接口 | 方法 | 功能 |
|------|------|------|
| `/send` | POST | 发送消息 `{receiver_id, receiver_type, content, item_id?}` |
| `/conversation` | GET | 获取与某人的会话历史（参数：other_id, other_type, limit），同时将对方消息标记为已读 |
| `/conversations` | GET | 获取当前用户的所有会话列表（含对方信息、最后消息时间、未读数） |
| `/unread` | GET | 获取未读消息总数 |

**会话查询核心**：
- 查询双方互为发送/接收的所有消息
- 按时间正序排列
- 标记对方发来的消息为已读

**会话列表核心**：
- 找出所有与当前用户有过消息往来的对方
- 补充对方用户信息（姓名、编号）
- 计算每个会话的未读数
- 按最后消息时间倒序

#### `路由/留言.py` — 物品留言 API

**蓝图前缀**：`/api/items/<id>/messages`

| 接口 | 方法 | 功能 |
|------|------|------|
| `/` | GET | 获取物品的所有留言（含留言者信息） |
| `/` | POST | 发布留言 `{content}` |

#### `路由/上传.py` — 文件上传 API

**蓝图前缀**：`/api/upload`

| 接口 | 方法 | 功能 |
|------|------|------|
| `/` | POST | 上传图片（multipart/form-data，字段 file） |

**处理逻辑**：
- 校验文件存在性和大小（≤10MB）
- 校验 MIME 类型（image/jpeg、image/png、image/gif、image/webp）
- 生成唯一文件名（`时间戳_随机ID.扩展名`）
- 保存到 `后端/上传文件/` 目录
- 返回可访问的 URL

### 3.4 业务层详解 (`业务/`)

#### `业务/认证服务.py` — 认证业务逻辑

**核心函数**：

| 函数 | 功能 | 业务规则 |
|------|------|----------|
| `校验注册数据(数据)` | 验证注册表单所有字段 | 身份必须是 teacher/student、编号非空、邮箱格式正确、密码≥6位、姓名非空 |

### 3.5 数据库表结构

#### teachers 表（老师表）
| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|

### 3.6 鉴权机制详解

**JWT Token 结构**：
```json
{
  "sub": 1,
  "身份": "teacher",
  "编号": "T2024001",
  "姓名": "张老师",
  "session": "abc123...（64位十六进制）",
  "iat": 1727000000,
  "exp": 1727086400
}
```

**认证流程**：
1. 用户登录 → 后端生成 session_token 写入数据库 → 签发 JWT 返回
2. 前端存储 JWT 到 localStorage → 每次请求带 `Authorization: Bearer <token>`
3. 后端 `从请求获取用户()` 解析 JWT → 获取 session_token → 对比数据库
4. 如果 session_token 不匹配 → 返回 401 → 前端提示"账号已在其他设备登录"

**单点登录原理**：
- 同一账号在新设备登录时，数据库的 `session_token` 被新值覆盖
- 旧设备的 JWT 中仍包含旧 session_token
- 旧设备后续请求被判定为"session 不匹配"→ 强制下线

## 五、业务流程详解

### 5.1 注册登录流程

```
用户打开登录注册页
    ↓
Tab 切换到注册 → 选择身份（老师/学生）
    ↓
填写：学号/工号 + 邮箱 + 密码 + 姓名 + 院系/班级
    ↓
前端校验（邮箱格式、密码≥6位、必填项）
    ↓
POST /api/auth/register
    ↓
后端：校验 → 查重（同表+跨表邮箱唯一） → 密码哈希 → INSERT
    ↓
生成 session_token → 签发 JWT → 返回 token
    ↓
前端存储 token → 自动跳转失物大厅
```

### 5.2 发布与审核流程

```
用户登录后 → 进入发布页
    ↓
选择类型（丢失/捡到）→ 选择分类 → 填写标题/描述/地点
    ↓
上传图片（可选）→ 预览确认 → 提交
    ↓
POST /api/items（audit_status=0 待审核）
    ↓
物品显示在"我的发布"中，状态为"审核中"
    ↓
老师登录 → 后台管理 → 审核管理
    ↓
查看待审核列表 → 单条/批量通过或拒绝
    ↓
┌ 审核通过 → audit_status=1 → 物品上架到失物大厅
└ 审核拒绝 → audit_status=2 + 反馈原因 → 物品从列表删除
```

### 5.3 标记已找到流程

```
发布者登录 → 进入自己的物品详情页
    ↓
前提条件：物品 audit_status=1（审核通过）且 status=0（未找回）
    ↓
点击"✅ 已找到"按钮 → 确认对话框
    ↓
POST /api/items/<id>/complete
    ↓
后端：检查发布者权限 → UPDATE status=1, found_at=NOW()
    ↓
物品卡片/详情页显示"已找到"印章
    ↓
3 天后：列表查询自动过滤（found_at < NOW() - INTERVAL 3 DAY）
    ↓
物品从失物大厅消失，但仍在发布者"我的发布"中可见
```

### 5.4 私聊流程

```
用户 A 查看物品详情（发布者为用户 B）
    ↓
点击"💬 和发布者私聊"按钮
    ↓
弹出聊天窗口 → 自动加载历史消息
    ↓
A 输入消息 → 回车/点击发送
    ↓
POST /api/messages/send {receiver_id, receiver_type, content, item_id}
    ↓
后端：写入 messages 表
    ↓
A 的聊天窗口立即刷新显示新消息
    ↓
B 下次打开会话时：消息自动标记为已读
```

### 5.5 批量操作流程

```
失物大厅/个人中心 → 点击"批量选择"
    ↓
卡片进入选择模式（显示复选框，隐藏操作按钮）
    ↓
点击卡片/复选框选中 → 顶部显示"已选 N 项"
    ↓
点击"全选" → 选中当前页所有
    ↓
点击"🗑 一键删除" → 确认对话框
    ↓
批量调用 DELETE /api/items/<id>（循环）
    ↓
刷新列表，显示删除后结果
```

## 六、部署说明

### 环境要求
- Python 3.11+
- MySQL 5.7+ / 8.0+
- pip 包管理器

### 部署步骤
1. 安装 Python 依赖：
   ```bash
   pip install -r 后端/requirements.txt
   ```

2. 配置数据库连接：编辑 `后端/配置.py`，修改 `DB_CONFIG` 为实际 MySQL 连接参数

3. 启动服务：
   ```bash
   cd 后端
   python 应用入口.py
   ```
   首次启动时会自动创建数据库表和迁移缺失的列

4. 局域网访问（可选）：以管理员身份运行 `开启局域网访问.bat`

### 目录权限
- `后端/上传文件/` 目录需要写入权限
- MySQL 用户需要 CREATE/ALTER/INSERT/UPDATE/DELETE/SELECT 权限
